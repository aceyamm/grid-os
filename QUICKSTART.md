# Quick Start Guide — Grid OS

## 🚀 Get Started in 2 Minutes

### Prerequisites
- **Node.js** 18+ ([download](https://nodejs.org))
- **npm** 8+ (comes with Node.js)
- **Git**

### Installation

```bash
# Clone the repository
git clone https://github.com/aceyamm/grid-os.git
cd grid-os

# Install dependencies
npm install

# Start development server
npm run dev
```

The application will open at **http://localhost:3000** automatically.

## 🎮 Using the Application

### Demo Scenario
Grid OS ships with a seeded utility scenario demonstrating a realistic grid disturbance:

1. The energy-focused **landing page** opens without a popup. Choose **Enter dispatch workspace** to enter; the system guide then opens inside the terminal.

2. Open **Workspace Options** on the landing page to:
   - Load temporary demo data without changing your saved workspace
   - Return to the last saved workspace
   - Start completely fresh after confirming replacement of saved cases

3. **Overview** loads immediately with:
   - Substation North-4 (SUB-N04) in ELEVATED status
   - Current load exceeding capacity (overloaded)
   - Transformer thermal derating (-35% capacity)
   - Seeded, clearly labeled simulation telemetry

4. **State Track** shows the 9-stage workflow:
   - Sage markers: Completed stages
   - Gold highlight: Current stage
   - Dedicated human authorization stage

5. **Node Telemetry** displays:
   - Current frequency (59.92 Hz — slightly low)
   - Capacity utilization (106% — overloaded)
   - Spinning reserves available (65 MW)
   - Active diagnostic logs with symptoms

Use the left navigation to open the asset board, scan findings, review gate, Continuum history, and simulation preview. **Agents** provides timed or manual process playback, replay from SCAN through SIGNAL, and a live trace; playback always pauses at SIGNAL for dispatcher review. **Tours & Practice** offers a tab-by-tab guided tour, a timed demo agent run that highlights each tab, and a temporary nine-stage practice tour with a simulated dispatcher gate. Tours do not modify the saved workspace. Standard mode stores the workspace in this browser; `?demo=true` uses temporary, non-persisted demo data.

### Progress Through Workflow

1. Review the current stage and enter a verification note
2. Select **Complete [stage]** to advance one stage
3. Completing `RESERVE` creates a recommendation and opens the human review gate
4. Enter a decision note and select **ACCEPT**, **REJECT**, or **HOLD AT STAGE**
5. Every transition and decision is appended to the in-session Continuum history

Grid OS records decisions only. It does not send commands to grid equipment. The simulation preview is synthetic and is not for operational use.

## 📦 Production Deployment

### Build the application:
```bash
npm run build
```

This creates an optimized `dist/` folder ready for deployment.

### Deploy to any static host:

**Vercel (recommended):**
```bash
npm install -g vercel
vercel deploy
```

**Netlify:**
1. Connect repository to Netlify
2. Set build command: `npm run build`
3. Set publish directory: `dist`

**Manual hosting:**
```bash
# Copy dist/ to your web server
scp -r dist/* user@server:/var/www/grid-os/

# Configure web server to serve index.html for all routes
# (SPA routing requirement)
```

## 📊 Understanding the 9-Stage Workflow

| Stage | What It Does | Required Input |
|-------|------------|---|
| **SCAN** | Collect telemetry snapshot | Verification note |
| **FAULT** | Identify faults and affected assets | Fault assessment note |
| **LOAD_CAP** | Calculate effective capacity with derating | Capacity verification note |
| **ISLAND** | Evaluate islanding boundaries | Islanding readiness note |
| **SEQUENCE** | Review switching/restoration plan | Plan verification note |
| **RESERVE** | Confirm spinning reserves | Reserve verification note |
| **SIGNAL** | Present agent recommendation (auto-generated) | Generated by system |
| **AUTHORIZE** | 🔒 Human dispatcher makes decision | ACCEPT / REJECT / HOLD + note |
| **SFAE** | Finalize audit trail | Auto-completes |

**Key Rule:** Each stage must complete in order. Missing or stale data blocks progression.

## 🎨 Customizing the Look & Feel

### Colors (Tailwind Theme)
Edit `tailwind.config.ts`:
```typescript
theme: {
  extend: {
    colors: {
      ink: "#050B0A",              // Background
      "dark-green-black": "#091310", // Cards
      border: "#20312B",            // Dividers
      cream: "#E8E9E3",             // Text
      // ... etc
    }
  }
}
```

### Fonts
Edit `src/styles/globals.css`:
```css
@layer base {
  body {
    font-family: Arial, Helvetica, sans-serif; /* Change here */
  }
}
```

## 🐛 Troubleshooting

### "Can't find module" error
```bash
npm install
```

### Build fails with Tailwind error
```bash
# Reinstall dependencies
rm -rf node_modules package-lock.json
npm install
npm run build
```

### Port 3000 already in use
```bash
# Use different port
PORT=3001 npm run dev

# Or kill process using 3000:
lsof -ti:3000 | xargs kill -9
```
